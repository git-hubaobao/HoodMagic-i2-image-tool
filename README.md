# HoodMagic小魔帽 - i2 生图工具

HoodMagic小魔帽 i2 生图工具是一个独立的桌面端 AI 图像创作工作台，基于 Electron、React 和 TypeScript 构建。它面向日常文生图、参考图生成、局部重绘、提示词模板沉淀、多会话项目管理、API 供应商切换和任务消费统计，适合把常用生图流程整理成一个可长期使用的本地工具。

项目已经从原始 monorepo 中独立出来，当前仓库只保留 i2 生图工具所需的应用层、存储层、任务队列、模型定义和接口适配代码。仓库不包含真实 API Key、用户历史图片、运行数据或安装包构建产物。

## 项目定位

- 桌面端优先：使用 Electron 打包为 Windows 安装包，也保留 macOS 和 Linux 的构建配置。
- 生图流程优先：围绕文生图、图生图、参考图上传、生成张数、局部编辑和历史复用设计。
- 本地数据优先：项目、会话、历史任务、提示词模板等数据保存在本机应用数据目录。
- 接口兼容优先：内置 Compatible API 模板，可对接标准 Images API 或兼容代理服务，并支持通过顶部 API 状态入口快速切换供应商。
- 可维护优先：应用被拆分为 workspace 包，核心模型、存储、任务和 provider adapter 独立维护。

## 核心功能

### 图片生成

- 文生图：输入提示词后直接创建生成任务。
- 图生图：上传参考图后使用同一提示词入口发起生成。
- 生成张数：支持 image2 API 的 `n` 参数，单次请求可选择生成 1 到 10 张图片，默认 1 张。
- 多尺寸预设：内置自动、1:1、16:9、9:16、2K 和 4K 横竖图等常用尺寸配置。
- 质量与格式配置：支持 `low`、`medium`、`high`、`auto` 质量，以及 `png`、`jpeg`、`webp` 输出格式。
- 多图结果：一次任务返回多张图片时会同时进入当前会话，可分别预览、保存、编辑、再次生成或另存为模板。
- 生成历史：结果会进入当前会话历史，历史记录关联项目、会话、模型、尺寸、质量、格式和生成张数。

### 参考图上传

- 点击输入区的加号选择本地图片。
- 支持复制图片后使用快捷键粘贴上传。
- 支持把图片文件直接拖入应用窗口上传。
- 参考图会参与当前输入框的生成请求，不需要额外切换页面。

### 图片预览与查看

- 点击结果图片可打开大图预览窗口。
- 鼠标滚轮缩放会以当前鼠标位置为锚点放大或缩小。
- 图片可自由拖动查看细节，不必等到放大到特定比例。
- 预览窗口会跟随应用窗口尺寸响应式变化，适合在不同窗口比例下检查图片。
- 支持适应屏幕、100% 查看、保存图片和关闭预览。

### 局部编辑

- 支持基于源图和 mask 的局部重绘流程。
- 内置画笔、橡皮、画笔大小、缩放、适应屏幕和 100% 查看等本地遮罩编辑工具。
- 支持 `compatible` 和 `original` 两种编辑模式。
- 兼容模式会以较小尺寸提交编辑请求，提高部分上游接口的成功率；原始模式会保留源图提交尺寸。
- mask 建议使用 PNG，尺寸需要与源图保持一致。
- 编辑结果会写回任务历史和当前会话，方便继续迭代。

### 多会话与项目管理

- 支持项目分组和多聊天会话。
- 初始状态不再默认创建“未分组”项目或默认会话，左侧列表会保持空状态，直到用户新建项目、聊天或直接发起生成。
- 未选择聊天时，可以直接在主界面输入提示词并生成，应用会自动创建新聊天；聊天可移动到指定项目或保持未归档状态。
- 支持项目新建、重命名、删除，以及会话重命名、移动项目、删除和恢复。
- 支持会话回收站，删除后的内容可集中管理。
- 历史记录与会话 ID、项目 ID 关联，便于按项目追溯创作过程。

### 提示词模板库

- 支持文生图模板和图生图模板。
- 支持模板分类、收藏、变量占位和默认值。
- 支持给模板附加预览图，作为本地资源保存。
- 支持导入单个模板或模板包。
- 支持导出单个模板、选中模板、分类模板或全部模板。
- 支持批量选择、批量移动分类、批量删除和调整模板卡片大小。
- 支持打开本地模板文件夹，并扫描导入目录中的模板文件。
- 支持把当前生成提示词和结果预览图另存为模板，方便沉淀常用风格。

### API 模板与配置

- 内置 Compatible API 模板。
- 默认 Base URL 为 `https://api.openai.com`。
- 默认生成接口为 `/v1/images/generations`。
- 默认编辑接口为 `/v1/images/edits`。
- 顶部 API 状态按钮会显示当前供应商/接口模板和连接状态，并可展开下拉菜单直接切换供应商。
- 设置面板中的供应商选择仅用于维护模板、Base URL、模型、Endpoint、API Key 和高级兼容参数。
- 支持在应用设置中新增、编辑、删除自定义 API 模板；内置模板受保护，不能删除。
- 支持生成接口和编辑接口分别配置 Endpoint Path。
- 支持按供应商模板配置是否发送 `output_format`、是否发送 `response_format`，并选择 `url` 或 `b64_json` 响应格式。
- 支持测试连接，显示请求端点、模型、尺寸、响应格式和上游错误摘要。
- API Key 按模板隔离保存，只应在应用运行时配置，不应写入仓库文件。

### 任务列表与消费统计

- 记录文生图、图生图和图片编辑任务的排队、生成中、成功、失败、取消状态。
- 统计总任务数、成功任务、失败任务、运行中任务、成功图片数和预计总消费。
- 支持默认单张价格和当前 API 模板单价配置，费用按成功图片数估算。
- 支持按 API 模板、任务状态、任务类型和时间范围筛选任务记录。
- 支持导出任务统计 CSV，或仅清空任务统计记录而保留会话、图片历史、模板和 API 设置。

### 主题与界面

- 支持深色和浅色主题切换。
- 支持中文和英文界面切换。
- 桌面端窗口、侧边栏、聊天区、输入区和设置区围绕高频生图工作流组织。

安装依赖：

```bash
pnpm install
```

启动开发环境：

```bash
pnpm dev
```

启动后会打开 Electron 桌面窗口。首次使用需要在应用设置中配置 API Base URL、模型和 API Key。

## 使用流程

1. 启动应用并进入设置。
2. 选择内置 Compatible API 模板，或创建自定义 API 模板。
3. 配置 Base URL、生成 Endpoint、编辑 Endpoint、模型名和 API Key，可按需启用输出格式、响应格式等兼容参数。
4. 使用“测试连接”确认当前接口可用。
5. 回到主界面，顶部 API 状态按钮会显示当前供应商；需要切换供应商时可直接从该按钮展开选择。
6. 在输入区选择尺寸、质量、格式和生成张数，然后输入提示词生成图片。
7. 需要参考图时，可以点击加号、粘贴图片或把图片拖入窗口。
8. 点击生成结果查看大图，使用滚轮和拖动检查细节。
9. 需要局部重绘时，在结果图上点击“编辑图片”，涂抹 mask 后提交编辑。
10. 对满意的提示词和结果保存为模板，后续在模板库中复用。
11. 在任务列表 / 消费统计中查看任务状态、图片数量和预计费用，必要时导出 CSV。

## 数据与安全边界

本仓库只保存源代码、配置模板、文档和测试，不保存运行期隐私数据。

不应提交到 GitHub 的内容包括：

- 真实 API Key、token、cookie 或代理鉴权信息。
- 用户生成历史图片。
- 应用运行时的数据文件。
- 私有提示词模板库。
- `node_modules`、`out`、`dist`、release 安装包等构建产物。

API Key 应在应用设置界面中配置。本地运行数据由 Electron 的用户数据目录管理，仓库中的 `.env.example` 只作为安全提示，不包含真实密钥。

## 常见问题

### 启动后无法生成图片

先检查顶部 API 状态显示的供应商是否正确，再检查应用设置中的 Base URL、生成 Endpoint、模型名和 API Key。兼容代理服务还需要确认生成接口、编辑接口、`output_format`、`response_format` 和 `n` 参数是否与标准 Images API 行为一致。

### 参考图没有被带入请求

确认图片已经显示在输入区附件列表中。支持的上传方式包括点击加号、粘贴剪贴板图片、拖拽图片文件到窗口。

### 局部编辑请求失败

优先检查源图和 mask 的尺寸是否一致，mask 是否为 PNG，以及上游接口是否支持 `/v1/images/edits` 的 multipart 提交。

如果原始尺寸编辑失败，可以切换到兼容模式重试；兼容模式会缩小提交尺寸，不影响原图保存和文生图 4K 生成。

### 一次任务没有返回所选张数

生成张数对应 image2 API 的 `n` 参数，表示单次请求期望返回的图片张数。若上游只返回部分图片，请检查所选供应商是否支持该 `n` 值，以及任务列表中的错误摘要或上游响应。

### 顶部 API 状态和设置里的供应商有什么区别

顶部 API 状态按钮用于查看当前聊天正在使用的供应商，并可直接展开切换。设置面板里的供应商区域用于维护模板、密钥、模型和 Endpoint 等配置。

### 打包失败

先确认依赖安装完整、Node 版本符合要求，并重新执行：

```bash
pnpm install
pnpm build
pnpm package
```

如果是 Windows 安装包构建失败，还需要确认 electron-builder 依赖下载是否可访问。
